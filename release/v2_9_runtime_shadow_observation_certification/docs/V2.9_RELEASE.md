# V2.9 Runtime Shadow Observation Certification + Cleanup

## Purpose
Certify the V2.8.2 hook structurally and from accumulated runtime ledgers, without changing strategy or order behavior.

## Cleanup
Safely removes only the known failed V2.8/V2.8.1 intermediate files left untracked in the working tree. Every target is checked with `git ls-files --error-unmatch`; tracked paths are never deleted.

## Certification
- compile `paper_daily_session/runner.py`
- require exactly one shadow method and one polling-loop call
- inspect V2.8.1 hook ledger status counts
- verify no hook row reports primary Paper flow blocked
- verify no hook row reports broker/Paper/live order writes
- inspect V2.7 signal/outcome ledger
- reject duplicate signal IDs, duplicate outcome IDs, and orphan outcomes
- report current Paper session ledger state

## Runtime states
`PASS_WAITING_FOR_RUNTIME_OBSERVATION` is expected when the hook has been installed but the real Paper polling session has not run since installation (for example during market closure).

After runtime records exist:
- partial observation is reported for fewer than 3 successful hooks
- full observation is `PASS_RUNTIME_SHADOW_OBSERVED` after at least 3 successful hooks

No automatic promotion occurs.

## Safety
V2.9 changes no Paper runtime logic, production parameters, selector, broker behavior, or order submission.
