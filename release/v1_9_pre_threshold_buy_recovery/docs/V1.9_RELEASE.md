# V1.9 Pre-Threshold BUY Recovery Counterfactual + 1D Warm-up Normalization

## Goal
Determine whether holdout zero-trade behavior is mainly caused by:
1. the initial 1d feature warm-up gap,
2. confidence calibration penalty,
3. the 0.75 selector threshold,
4. or genuine directional SELL/HOLD consensus.

## Method
- Reuse V1.7.3 recovered real Alpaca 75-day source.
- Reuse canonical `shadow.make_checkpoints` and `shadow.analyze_at_rows`.
- Preserve full canonical analysis objects, including `raw_confidence`, `calibrated_confidence`, consensus, reward-risk and per-timeframe signals.
- Warm-up normalization means excluding checkpoints where the canonical seven-timeframe feature set is incomplete. It does NOT fabricate or backfill synthetic 1d features.
- Counterfactual selector thresholds are tested at 0.50, 0.55, 0.60, 0.65, 0.70, 0.73 and 0.75 while keeping reward-risk >= 1.0.
- Compare calibrated confidence against existing raw confidence at the same thresholds.
- Decompose MSFT selected-SELL checkpoints by the seven canonical timeframe signals.

## Safety
No production threshold change, no raw confidence deployment, no strategy/risk change, no Paper runtime change, no broker write/order submission, and no automatic promotion.
