# V3.4.1 Runtime Import Repair

## Root cause
V3.4 passed static/unit verification because the repo root was on `sys.path`, but the actual dashboard server is launched directly as:

`C:\stock-bot\dashboard\operations_dashboard_v3_2.py`

In direct-script mode, `from dashboard.visualization_v3_4 import ...` can fail because Python's import root becomes the dashboard directory.

## Repair
Load the existing visualization adapter by exact file path with `importlib.util.spec_from_file_location`.

The adapter remains:

`C:\stock-bot\dashboard\visualization_v3_4.py`

No duplicate adapter or engine is created.

## Verification
The verifier launches the real dashboard server as a direct script on temporary localhost port 8874 and requires:
- `/api/status` success
- visualization status PASS
- 10 validation slots

Then the one-click script restarts the real dashboard on port 8766 and verifies PASS again.

## Safety
No broker network/write, no order submission, no Paper runtime changes, and no strategy/risk/selector changes.
