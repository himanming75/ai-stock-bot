# V1.7.4 Fast Holdout Audit

V1.7.3 successfully recovered 75 days of real Alpaca data but the root-cause audit was computationally expensive.

This repair does not fetch data again and does not create a new strategy/analyzer/lifecycle engine.

Performance changes only:
- pre-index historical rows by timestamp;
- use binary-search slicing rather than rescanning every row at every checkpoint;
- analyze each target checkpoint once and cache the canonical result;
- constrain canonical rolling_lifecycle checkpoint generation to the target holdout dates;
- reuse cached canonical analyzer outputs inside lifecycle replay.

Source:
`runtime/v1_7_3_holdout_recovery/alpaca_real_historical_holdout_75d.jsonl`

No network, broker writes, orders, Paper runtime change, or production parameter change.
