# V2.9.3 Stale Session Lock Safe Recovery + Runtime Readiness Certification

## Confirmed blocker
V2.9.2 found the exact scheduled task ready and correctly pointed at:
`C:\stock-bot\RUN_PAPER_AUTONOMOUS_DAILY_SESSION.ps1`

The only runtime blocker was:
`runtime/paper_autonomous_daily_session/session.lock`

The lock referenced PID 22144, and that PID was no longer alive.

## Recovery policy
V2.9.3 does not blindly delete the lock.

It:
1. reads and parses the lock;
2. obtains the recorded PID;
3. checks the PID again with `Get-Process`;
4. blocks if the process is alive;
5. backs up the stale lock;
6. verifies the backup exists;
7. removes only the stale lock;
8. re-runs V2.9.2 readiness audit.

## Safety
- does not start Paper runtime
- does not start/modify/enable Scheduled Tasks
- does not remove STOP
- does not change strategy or selector
- no broker write
- no Paper/live order submission
- no automatic promotion
