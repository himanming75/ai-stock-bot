# V2.7 Real-Time Shadow Candidate Strategy

## Purpose
Run the V2.6-passed regime-aware BUY candidates beside the existing Paper system without changing or submitting anything.

## Locked candidates
- MSFT_ONLY_30M: MSFT, 15-minute same-symbol dedup, 30-minute horizon, 5 bps diagnostic cost.
- MSFT_NVDA_30M: MSFT + NVDA, 15-minute same-symbol dedup, 30-minute horizon, 5 bps diagnostic cost.

## Runtime behavior
`tools/run_regime_aware_shadow_v2_7.py` performs one read-only shadow cycle:
1. Read the existing primary historical/runtime market-data file.
2. Reuse canonical checkpoint builder, truncation, analyzer, feature audit and production candidate observation.
3. Detect canonical BUY actions where 1d signal is SELL.
4. Apply only the locked V2.6 candidate symbol/de-dup definitions inside the shadow namespace.
5. Append SHADOW_SIGNAL records.
6. When enough subsequent market-data bars are present, append SHADOW_OUTCOME records with 30-minute gross and 5 bps net return.
7. Write `latest_shadow_snapshot.json`.

The script can be invoked repeatedly by the user's existing local orchestration. It does not create its own broker connection or background service.

## Output
`runtime/regime_aware_buy_shadow_v2_7/shadow_candidate_ledger.jsonl`
`runtime/regime_aware_buy_shadow_v2_7/latest_shadow_snapshot.json`

## Safety
- no TradingClient
- no broker write
- no Paper order
- no live order
- no production selector modification
- no production parameter modification
- no automatic promotion
- no network use by V2.7 itself
