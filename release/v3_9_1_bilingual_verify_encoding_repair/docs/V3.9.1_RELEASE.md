# V3.9.1 Bilingual Verify Encoding Repair

V3.9 RUN and unit tests passed, but Windows PowerShell failed to parse VERIFY_V3_9.ps1 because Korean UTF-8 literals were decoded with the wrong legacy code page.

Symptoms included mojibake such as question-mark/Korean fragments and parser errors:
- Missing ')' in method call
- Unexpected token
- missing string terminator
- Try missing Catch/Finally

V3.9.1 removes all non-ASCII text from the PowerShell verifier. Live Korean UI verification is delegated to a Python UTF-8 helper, which:
- downloads the actual dashboard HTML from localhost
- strictly decodes UTF-8
- verifies required Korean labels
- returns a non-zero exit code on missing labels

This preserves the V3.9 canonical performance unification and bilingual UI without relying on PowerShell's source-file encoding behavior.

Safety: dashboard verification/analytics only. No broker write, order submission, Paper runtime modification, production parameter change, or duplicate trading engine.
